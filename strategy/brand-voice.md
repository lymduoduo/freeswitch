# 品牌声音策略 / Brand Voice Strategy

## 品牌声音定义 / Voice Definition

**核心关键词**: 直接、务实、有深度、不废话

**English Voice Statement:**
> Write like a senior engineer explaining to a smart colleague over coffee — precise, opinionated, grounded in real experience, no marketing fluff.

**中文声音陈述：**
> 像一个资深工程师在喝咖啡时向聪明同事解释问题——精准、有立场、基于真实经历，没有营销废话。

---

## 声音四维度 / The 4 Voice Dimensions

### 1. 直接 / Direct
- **是**: "FreeSWITCH 的 NAT 处理经常让人崩溃，因为它默认行为反直觉。"
- **不是**: "FreeSWITCH 在某些网络环境下可能会遇到一些配置方面的挑战。"

### 2. 务实 / Pragmatic
- **是**: "用这个方案的前提是你的并发量 < 500路，超过就不划算了。"
- **不是**: "这个方案在大多数场景下都能工作。"

### 3. 有立场 / Opinionated
- **是**: "我认为大多数团队不应该自建 SIP 代理，除非你有这三个理由……"
- **不是**: "自建 SIP 代理有它的优缺点，每个团队情况不同。"

### 4. 真实 / Authentic
- **是**: "这个 bug 让我调试了两天，最后发现是 RTP 时序问题。以下是我的排查过程。"
- **不是**: "通过系统性的调试方法，我们可以高效地定位 RTP 相关问题。"

## 写作风格指南 / Writing Style Guide

### 结构
- 开篇直接切入问题或结论（不要暖场废话）
- 用具体数字代替模糊描述（"延迟 < 200ms" 而非 "延迟很低"）
- 代码示例优先于文字描述
- 结尾给出明确的行动建议或判断

### 语气
- 第一人称 "我" / "我们" （不用被动语态逃避责任）
- 承认不确定性："我没有测过这种场景，但我的判断是……"
- 不装全知：指出权衡和边界条件

### 术语使用
- 专业术语直接用，不过度解释（读者是工程师）
- 首次出现缩写时给出全称：Session Initiation Protocol (SIP)
- 中英文混用时保持一致性

## 禁用词列表 / Words to Avoid

| 避免 | 替代 |
|------|------|
| "赋能" / "empower" | 具体说明做了什么 |
| "生态" / "ecosystem" | 具体指哪些工具/系统 |
| "最佳实践" / "best practice" | "在这种场景下，我用这个方法" |
| "无缝" / "seamless" | 描述具体的集成方式 |
| "革命性" / "revolutionary" | 数据和事实说话 |
| "轻松" / "easy" | 承认复杂性 |

## 不同平台的声音调整 / Platform Voice Adjustments

| 平台 | 调整方向 | 示例 |
|------|---------|------|
| 技术博客 | 最完整，可以长，有深度 | 完整文章，代码+架构图 |
| Twitter/X | 更直接，略带个性，单点洞见 | "SIP 的 NAT 问题不是 bug，是设计如此，原因是..." |
| LinkedIn | 稍正式，强调工程影响和结果 | 项目结果 + 技术决策说明 |
| Newsletter | 私密感，像写信，可以更个人 | "这周我发现了一个有趣的问题..." |

---

## 内容质量检查清单 / Quality Checklist

发布前问自己：
- [ ] 开头有没有在说废话？（删掉前两句试试）
- [ ] 有没有具体的数字、代码或案例支撑观点？
- [ ] 这篇文章里的"我"是真实的还是表演出来的？
- [ ] 一个正在解决这个问题的工程师读完会有收获吗？
- [ ] 有没有给出明确的结论或建议？
